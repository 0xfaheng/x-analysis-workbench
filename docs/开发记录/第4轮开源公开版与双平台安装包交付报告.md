## 公开版首次使用流程

1. 从公开仓库 Releases 选择 Windows 安装包 / 便携 ZIP，或 Mac arm64 DMG / ZIP。Mac 将应用拖入「应用程序」，首次按安装说明处理安全拦截。
2. 在设置卡片填写自己的 X 用户名，支持带或不带 @，限 1–15 位字母、数字、下划线；保存只修改 config.local.json 的 handle，其他键保留。
3. 点「登录 X」，在系统 Edge / Chrome 的工作台专用配置窗口手动完成验证；确认账号后关闭。
4. 点「仅更新数据」，查看本期报告。Windows 顺序为 Edge → Chrome，Mac Playwright 为 Chrome → Edge，Linux 再尝试自带 Chromium。
5. macOS 若发现 ego-browser，更新数据仍优先 ego。ego 用户需在 ego 会话登录同一账号；「登录 X」按钮只管理 Playwright 会话，可显式选 backend=playwright 统一使用专用窗口。
6. 默认本机数据位于 Documents/X分析工作台；Windows 便携版、XWB_ROOT 和源码 root 优先级沿用旧行为。Mac 冻结 .app 默认使用 Documents；个人策略首次由模板生成，以后不覆盖。

## 首次 CI 最可能失败的位置

1. **Windows / Mac 的本地浏览器集成测试**：runner 系统浏览器与 Playwright 版本、企业策略、下载事件或时序变化。此部分本机按要求完全未启动浏览器，优先查看 test_full_collection_and_logged_out 的日志。
2. **macos-latest 的架构与 PyObjC 收集**：发布 job 显式要求 arm64 Python，脚本检查 arm64；若 runner 实际不是 Apple Silicon，或 pip 依赖 / 驱动平台不匹配，会明确失败。发布必须核对 runner 的 uname、Python 架构及 PyInstaller 日志。
3. **Windows Inno Setup / WebView2 / pythonnet**：编译器发现、Chocolatey 安装、语言包路径和冻结资源差异仍需首次原生构建确认。
4. **Release 权限**：publish job 需要内容写权限，两侧构建有一侧失败就不发布；已有同名 Release 也会使 gh release create 失败。
