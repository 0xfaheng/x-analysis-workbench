## 命令行

Windows 在工作台根目录安装 Python 3.10+ 和系统 Microsoft Edge 后：

```powershell
pip install -r requirements.txt
python scripts\run_weekly.py --login
python scripts\run_weekly.py
python scripts\run_weekly.py --skip-collect --date 2026-10-17
python scripts\run_weekly.py --backend playwright --root "D:\X分析工作台"
```

默认使用 `channel="msedge"`，不额外安装浏览器。`--login` 固定使用 Playwright 专用配置且强制显示窗口，只等待用户手动登录目标账号；关闭窗口且未确认目标账号返回 3。它不采集、不分析，且与 `--skip-collect` 互斥。

Mac 沿用 `./scripts/run_weekly.sh` 和 `./scripts/run_weekly.sh --skip-collect --date 2026-10-17`。`--backend auto` 在 macOS 找到 ego-browser 时选 ego，其余平台选 Playwright；也可显式指定 ego/playwright。找 ego 的顺序为 PATH、`~/.local/bin/ego-browser`。根目录优先级为 `--root`、`XWB_ROOT`、脚本上级目录。

可选 `config.local.json` 递归覆盖 config.json。`collector` 默认值为 backend=auto、browser_channel=msedge、profile_dir=browser-profile、headless=false、base_url=https://x.com。profile_dir 的相对路径以 root 为基准。channel 可改为 chrome 或空字符串；只有空字符串使用的 Playwright Chromium 需单独安装。采集窗口不主动置顶，登录模式始终有窗口。

## 退出码

| 代码 | 含义 |
|---|---|
| 0 | 成功；登录模式已确认目标账号 |
| 2 | 参数或配置错误 |
| 3 | 未登录目标 X 账号；登录窗口关闭且未确认登录 |
| 4 | 采集/连接/页面失败，外部浏览器占用配置目录，或分析渲染输入/文件错误 |
| 5 | 缺少 markdown；Mac 包装找不到带 markdown 的 Python |
| 6 | 缺少 Playwright，或指定 Edge/Chrome/Chromium 不存在 |
| 7 | 已有采集/分析或登录任务在运行（含另一个工作台任务使用相同配置目录） |

`<root>/data/.run.lock` 覆盖登录、采集、分析和渲染；`.run.lock.guard` 是常驻的短临界区系统锁文件。锁记录超过 2 小时或 PID 不存在可回收，旧任务不能删掉新所有者的锁。Windows 使用只查询进程的原生 API，不使用 `os.kill(pid, 0)`。浏览器配置目录还持有 `.xwb.lock`，并在启动前探测 Chromium 的 SingletonLock/Windows lockfile，启动时的原生占用错误也会给出中文说明。

## Playwright 选择器与步骤对照

所有 Playwright 导航地址均通过 `build_url(base_url, route)` 拼接；base_url 支持本地 HTTP 模拟站点和路径前缀。等待时长集中为模块顶部的 `*_MS` 常量。

| 步骤 | ego 写法 | Playwright 写法及产物 |
|---|---|---|
| 1. home 登录检查 | `waitForSelector("loc=css:[data-testid='SideNav_AccountSwitcher_Button']")`，evaluate 读 innerText | `locator(ACCOUNT_SELECTOR).wait_for(...)` + evaluate 读相同节点；完整匹配目标 @handle；未登录写 meta 后停止 |
| 2. 原创内容奖励资格 | evaluate：`main || body` 内找 svg，path 的 d 以 `M12 1.75C6.34` 或 `M12 3.75c` 开头，向上找含 p 的行 | 相同 DOM JavaScript 通过 `page.evaluate(ELIGIBILITY_JS)` 执行；保存 `eligibility.json` 的 text/items/text/icon |
| 3a. 概览 3M | `text="3M" >> nth=0` | `get_by_text("3M", exact=True).first.click()`；相同 main/body 文本快照为 `overview_all_3m.txt` |
| 3b. 全部/仅认证切换 | evaluate 读 `main button[aria-label='Verified only']` 的 aria-pressed；`loc=role:button[name='Verified only']` 点击 | `locator("main").get_by_role("button", name="Verified only", exact=True)`；`get_attribute("aria-pressed")` 后按需点击；缺失仍按原规则记录 warning、跳过认证导出 |
| 3c. 概览 CSV | `waitForEvent("download")` 与 `loc=css:button[aria-label='Download CSV'] >> nth=0` 并发 | `with page.expect_download(...)` 包住 `get_by_role("button", name="Download CSV", exact=True).first.click()`；保存 `overview_all.csv` / `overview_verified.csv` 和认证文本 `overview_verified_3m.txt`；随后恢复全部开关 |
| 4. 90 天帖子 | 导航 `i/account_analytics/content?type=posts&sort=date&dir=desc&days=90`，同一下载按钮 | 相同 route/query，复用上述原生下载选择器；保存 `content_90d.csv` |
| 5. 28D 受众 | `text="28D" >> nth=0`，evaluate 读 `main || body` 文本 | `get_by_text("28D", exact=True).first.click()` + 相同正文读取；保存 `audience.txt`；切换失败仍 warning 并保留默认范围 |
| 收尾 | `task.finish({keep: []})`，失败写 reason/error/step | `context.close()`；成功/失败保存 meta.json，保留最初失败或未登录结果 |

meta 保留 started_at、finished_at、handle、files（目标文件名到建议下载名）、warnings、ok，以及失败时的 reason/error/step、未登录时的 account_seen。两个后端均新增 backend；Playwright 没有 ego Space，因此 space_id 为 null。分析层不按 backend 分支。

最容易随 X 改版失效的是英文 `Verified only` / `Download CSV` 标签、3M/28D 控件、aria-pressed 的状态表达，以及资格图标 SVG path 和 p 行结构。账号 data-testid、Analytics 路由、CSV 列名和英文日期格式也需要实机核对。当前按原采集器保留固定等待和认证开关缺失的降级规则；资格页有文字但结构改变时仍可能采到空 items，需人工核对，不能仅凭离线单测确认线上页面兼容。

## 独立审查与局部修复

- 修复第一轮 atomic_write_text 将 0644 降为 0600 的问题；新建文件遵从 umask，已有权限保持。
- 增加跨进程锁和安全的陈旧锁回收；覆盖 `--login`，并防止旧任务释放新任务的锁。
- 修正 categories 的说明为“命中最多胜出，平局按配置顺序”，分类实现和关键词不变。
- ego 退出 0 但没有有效成功 meta 时，入口返回 4 并补存错误元数据，避免继续分析旧 CSV；ego 自身的任意非零代码仍按旧约定映射 4，明确未登录除外。
- Playwright 完整匹配账号，避免用户名的前缀碰撞；CSV 临时下载后原子替换，文件占用失败保留旧文件并提示关闭 Excel。
- 关闭浏览器的次要错误不能覆盖原始异常或未登录结果；用户在登录导航中关闭窗口也按未登录结束。

## 测试与离线验收

规定命令：

```bash
/Library/Frameworks/Python.framework/Versions/3.13/bin/python3 -m unittest discover -s tests
```

结果：81 项全部通过，0 跳过。Playwright 相关单测均使用模拟导入或模拟对象，缺失依赖路径也通过模拟覆盖，不启动浏览器。只读环境检查发现指定解释器当前可找到 playwright，这与任务背景的环境描述不同；测试仍不依赖其存在。Node/zsh 的现有语法检查和网页脚本 DOM 替身测试也通过。

可选依赖缺失验证：同一解释器加 `-S -m unittest discover -s tests`，81 项测试成功，按预期跳过 18 项依赖 markdown 的测试。

兼容性：修改前先使用第一轮合成夹具生成基线，再在临时中文路径工作台通过当前 `.sh --skip-collect --date 2026-10-17 --root <临时目录>` 运行；history.json、analysis.json、report.md、report.html、index.html 五个产物与修改前逐字节一致。真实数据只读指纹核对，未用于端到端测试，未执行针对真实目录的重生成。
