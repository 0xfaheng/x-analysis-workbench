# 程序建议与 X 官方规则

从 2.2.0 起，「更新数据与建议」会在本机依次完成只读采集、统计、下周建议与网页生成。普通用户无需接入 AI、填写 API Key 。旧版中的「仅更新数据」对应这个入口。CLI 与 Mac 包装入口也默认生成建议。

## 建议如何生成

`scripts/recommendations.py` 读取分析结果和随软件分发的 `rules/x-official-rules.json`，输出每条建议的数据依据、动作、下周复查方法及来源。结果保存在 `analysis.json` 的 `recommendations` 中，并写入报告第8节；第9节展示官方规则摘要与链接。

官方规则与运营实验分别标注。发帖数量、语言、题材、中位曝光等来自本机目标或数据观察，不是 X 对所有账号的统一要求。分类使用关键词，样本数量只是观察门槛。程序不推断推荐算法，不以相关性解释因果，不承诺收入或达标时间。

下一期有结构化计划时，程序复查可观测指标，结果为「指标达标」「指标未达标」「数据不足」或「需人工核对」。这些结果不能证明用户执行过建议，也不能证明建议造成了增长。缺少原始数据时不会当作0；年龄、本人地区、身份、收款、原创权属、完整媒体及社区注释等仍需本人核对。

## 官方来源与时效

规则快照版本及人工核验日期为 **2026-10-17**。摘要仅覆盖与工作台有关的要点，完整规则见：

- [X 原创内容奖励说明](https://help.x.com/en/using-x/original-content-rewards)
- [X 创作者变现标准](https://help.x.com/en/rules-and-policies/content-monetization-standards)
- [X 真实性规则](https://help.x.com/en/rules-and-policies/authenticity)
- [X 自动化规则](https://help.x.com/en/rules-and-policies/x-automation)

程序不会在每次分析时联网核实规则。超过30天或核验日期异常时，会在建议最前方提示复核；它使用已核验快照作为参考，不声称掌握最新条款。维护者应阅读官方页面、核对条款与适用计划，再更新 JSON 的摘要、门槛、版本及 `verified_at`，测试后随新版本分发。仅重新运行报告不会刷新核验日期。

官方快照中的门槛不接受个人 `program` 配置改写；该配置的原值保留在 `analysis.json.configured_target_90d` 供核对。个人运营目标通过 `phase_targets` 调整。官方条件全部满足仍不代表平台批准加入计划。

奖励计划对自动创建或发布内容的资格限制，与平台一般自动化规则的允许范围不同。工作台只生成分析和复盘任务，不生成可冒充本人经历的成品帖，不自动发布、点赞、回复、删除或修改账号。

## 个人目标与人工修改

在 `config.local.json` 配置自己的 `phase_targets`、`categories`；公共配置是 AI/web3 中文创作者示例，其他用户应按自己的方向调整。字典递归覆盖，阶段数组整体替换。可设置 `recommendations.min_sample_posts`（整数，至少2，默认5），它决定内容方向对比的最小观察样本量。

程序建议位于 `SUGGESTIONS:START/END` 内，包含 `AUTO-SUGGESTIONS` 标记和校验值。未编辑的程序建议每次分析时自动更新。手工改动建议后，后续分析会原样保留该区块，不再当作可自动复查的程序计划。旧版占位文字首次重算时会迁移为程序建议。

如果希望重新启用自动建议，先备份人工内容，再将 `SUGGESTIONS:START/END` 之间的内容替换为旧版占位文字 `（待助手填写：按 docs/周报流程.md 第 3 步撰写）`，然后重新生成网页。不要只删校验标记，否则会被当作人工内容保留。

人工修改建议后，同样遵循保留机制。
